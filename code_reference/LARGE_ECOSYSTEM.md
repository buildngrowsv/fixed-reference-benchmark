# Does an early copy protect an existing skill while a wide model learns a new codebase?

The two 238M models stayed within 0.002 bits per byte of each other on held-out CPython. They differ in where their final block gets 192 values. One uses the exact early copy. The other uses late working values. Test whether this structural difference affects forgetting when the same pretrained models learn code from new projects. The earlier 26.83M runs had similar CPython penalties under ordinary external adaptation. [Held-out wide scores](large_study/sealed_held_out/README.md) · [Original ecosystem protocol](ECOSYSTEM.md)

Restore both 16,384-update checkpoints. Reset AdamW for each and train 2,048 updates with the first 2,048 batches of the archived scientific-Python stream, sampling code from NumPy, SciPy and Matplotlib, without old-domain replay. Use 128-step warmup, peak 0.0004 / 3, weight decay 0.03 and norm cap one for both. This spends 16,777,216 target bytes per arm including repeat exposure. Evaluate the same 3,072 windows in six external projects before and after the adaptation. Evaluate original-domain loss on the fixed 2,048 CPython test windows. Comparisons within the two 238M arms are paired by windows and training order. Across scales, optimizer rate and adaptation duration differ.

The retention contrast subtracts early- and late-copy changes in CPython loss. Evidence of useful early retention requires at least 0.03 bits per byte less forgetting in the sealed arm with a negative upper paired 95% bound, plus a sealed-minus-late post-adaptation upper bound of +0.02 on the external macro mean. The old-domain interval resamples CPython package groups. The external interval resamples files within each fixed project. Report absolute losses and both directions of adaptation for transparency. This test uses a single starting checkpoint pair and one adaptation sequence. At the recent 49,000 bytes per second, the matched fits take about 12 minutes before evaluation overhead.
