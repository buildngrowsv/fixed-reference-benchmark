# Does sealing a 192-value early reference justify a narrower network?

The original 26.83M-parameter sealed model used 16.13% fewer weights than the readable model and retained similar accuracy on CPython and six external Python projects. Its equally compact late-copy control retained most of the benefit. Scale this specific architectural comparison after both wide baseline arms demonstrate basic learning on CPython. [Earlier CPython comparison](sealed_study/README.md) · [External projects](ecosystem_study/README.md)

Use width 1,536, a 192-coordinate early copy, and seven middle blocks with width 1,344. Fit two compact models at seed 101 on the same 4,096 updates as the 285M readable reference. In one arm the early region from block 2 reappears unchanged at the entrance to block 10. In the matched control those positions are filled from the final working state. Weights and initialization match within the compact pair. Save per-window scores on the same 1,024 validation windows and paired package intervals for sealed minus readable and sealed minus late-copy. A full held-out test is worth the additional training only if the sealed arm stays within +0.02 bits per byte of the wide readable model, or if it improves on the equal-size control by at least 0.02 with a negative upper bound. This is a validation screen. Reserve the final test windows for the selected follow-up.

## Matching the recovered baseline

The original wide readable and writable arms both missed the 3.24 validation bits-per-byte gate. If both recovery arms pass it, run the two 238,269,312-parameter compact arms at the same reduced peak learning rate of 0.0004 / 3. Keep seed, optimizer, 4,096 steps, byte windows, and width fraction matched to that recovered baseline. A difference in learning rate between the readable and sealed models would make the comparison ambiguous. We registered this follow-up before either recovery arm had produced a validation score. [Recovery protocol](LARGE_FIXED.md)

Apply the +0.02 compactness margin to the **upper 95% package-paired bound** of sealed minus readable. For the alternative early-copy criterion, require a mean sealed minus late-copy difference of −0.02 bits per byte or lower and a negative upper bound. Report the absolute loss of all three models. Either criterion qualifies a held-out continuation. The screen uses one training order. The 285M arms process about 42,600 context bytes per second. At that rate the two compact screens would take roughly 26 minutes together, before validation and checkpoint overhead.


## Held-out continuation

If the validation screen qualifies, restore each compact checkpoint with its optimizer state and continue to 16,384 steps at the same peak rate and paired data order. Compare both against the already completed 285M readable checkpoint on the identical 2,048 test windows. Continue both compact arms even when only one of the selection criteria passes. Report the +0.02 bound versus the readable model and the −0.02 point margin with a negative upper bound versus the same-size late copy. At the sealed arm’s observed 48,900 context bytes per second, the two continuations should take about 69 minutes before evaluation overhead.
