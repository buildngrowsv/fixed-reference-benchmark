# Can a reusable block make a fixed-reference model deeper for fewer weights?

Reuse one block seven times between the same input and output stages. At each pass it can read all channels and update 448 of 512. Each token keeps the other 64 coordinates exactly as they were when it entered. This is a forward computation with shared weights, distinct from a backward edge in a static graph. The original idea of an immutable reference does not itself require shared weights. Depth recurrence and cross-layer parameter sharing have established precedents. [Universal Transformers](https://arxiv.org/abs/1807.03819) · [ALBERT](https://arxiv.org/abs/1909.11942)

Choose one equal-parameter control. Initialize four unique blocks identically in both models and apply the middle protected block once in the control or seven times in the recurrent model. Also compare to the archived untied ten-block fixed-reference model trained on exactly the same CPython bytes. At 4,096 updates per arm, measure validation bits per byte, group-bootstrap differences over the same 1,024 windows, unique parameters, forward passes and training seconds. A storage benefit costs extra sequential computation relative to four ordinary blocks. The two small arms have identical initialization. The archived untied model shares the data order but differs in initialization and parameter count.

Continue their checkpoints to 16,384 updates only if the recurrent model beats the shallow model by at least 0.05 bits per byte with an interval fully below zero and finishes within 0.10 bits per byte of the untied model. Compare 2,048 fresh held-out windows at the final budget, retaining per-window data and group splits. No tuning by replay count. A positive screen calls for a matched-clock comparison before making any inference about compute efficiency.
