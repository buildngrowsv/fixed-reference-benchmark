# Can a compact model retain its original Python skill while adapting to other code?

Adapting the sealed model for 8,192 updates improved its held-out third-party loss by 0.19164 bits per byte and worsened its CPython loss by 0.21198. Hold its starting checkpoint, total updates, optimizer, batch size and budget fixed. Replace every eighth adaptation batch with an independently drawn batch from the original CPython training split. All other steps use exactly the earlier third-party examples. This spends one eighth of the same training budget on retention.

Compare the new checkpoint to the archived sealed checkpoint before and after ordinary adaptation, using fixed paired windows. Require preservation of at least 75% of the original gain on the six external projects and removal of at least half of the original CPython penalty. Compute paired loss relative to the corresponding linear combinations of the two archived window scores, with upper 95% bounds below zero on both endpoints. Use file clusters within external projects and package clusters for CPython. Report absolute losses and the direct external contrast versus ordinary adaptation. This is one declared replay allocation in a compact model. Its result cannot attribute retention differences to architecture. The run costs about five minutes on the Studio.
