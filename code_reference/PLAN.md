# Does a read-only early reference change next-byte learning on actual Python code?

Train two 10-block causal transformers from random initialization, width 512, eight attention heads, 512 input bytes per example, batch size 16. At the exit of block 2 reserve 64 channels per token. In the fixed arm the next seven blocks must reproduce those channels exactly; all channels are writable in block 10. In the second arm they are writable throughout but start with identical zero write projections. The arms use the same initial weights, examples, order, optimizer and targets. This tests a potentially useful or costly restriction on depth in ordinary autoregressive pretraining. Unlike the register pilot, every input position supplies a next-byte target.

Use the pinned CPython source archive 60403a5409ff2c3f3b07dd2ca91a7a3e096839c7, SHA-256 37c8e18b35e659da6ff4db74caea50ed4170cf66c6d51f97d22e436e338d7b5b. Train, validate and test only on .py files under Lib/. Group library packages (including their matching test modules where recognized) before deterministic hashing into 80/10/10 partitions. Deduplicate exact file contents globally. Keep windows within one file, sample files proportional to valid window count. Report file and byte counts, exact group membership and archive checksum. Similar implementations and vendored or boilerplate fragments can cross groups. This benchmark does not measure unconstrained code generation.

First establish that both implementations learn real code. Run 256 updates per arm and compare with a smoothed training-byte unigram on 256 fixed validation windows. Advance if the mean bits per byte of each arm beats unigram by at least 0.3 and is finite. Continue the exact checkpoints, including optimizer state and deterministic batch index, to 4,096 updates. Continue to 16,384 only if the mean validation score has improved at least 0.1 bits per byte since the 256-update screen and neither arm has become nonfinite. At the end each arm will have processed 134,217,728 context bytes. Use 128-step warmup to 0.0004, AdamW and norm clipping at 1. Checkpoint every 64 updates and report progress. The main endpoint is the fixed-minus-writable bits per byte on 2,048 fresh held-out windows; below zero favors the protected path. Secondary endpoint is the final ASCII byte of repeated identifier-like strings (at least four letters/digits/underscores, beginning with a letter or underscore, with a preceding instance at least 64 bytes earlier in the same context). Include overall byte top-one accuracy and a causal suffix-copy control that votes on following bytes of the longest earlier matching context up to length eight, backed off to the smoothed train unigram. All windows and targets are identical between arms.

Before opening final windows, compute the paired group-bootstrap interval on 1,024 validation windows. Replicate with a wholly new coupled initialization and data order only if the absolute difference is at least 0.02 bits per byte and the interval excludes zero. Record full per-window sums and counts for group-level replay. If neither architecture has a meaningful advantage, retire ordinary byte-model width sweeps at this scale.
