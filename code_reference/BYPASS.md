# Does a sealed forward reference buy comparable code prediction with fewer weights?

The original fixed model let all intervening blocks read its 64 protected values, although they could not change them. Test a true bypass on the same real CPython stream. Carry 64 of 512 channels directly from the exit of block 2 to the entrance of block 10. The seven intervening blocks see and compute on the other 448 channels only. The final block can read and update everything. Cropping attention and feed-forward weights reduces parameters and work while preserving ten block applications. This is a practical comparison of isolation and compression together.

Use seed 101 and the archived ten-block initial weight tensors, crop the leading channels of each attention projection independently within query, key and value, and crop the feed-forward hidden width to four times 448. Retain identical outer block and embedding initialization, batch order, update count, precision, optimizer, and validation windows. Compare the archived fixed-readable and writable controls at 4,096 updates. Continue the bypass alone to 16,384 if it has at least 10% fewer weights and its paired validation upper 95% bound is at most 0.05 bits per byte worse than the fixed-readable model. Report byte accuracy, throughput with the same checkpoint interval, parameter totals and paired package-bootstrap loss on the original held-out code windows. Identical validation/test panels permit matched contrasts, so this is a follow-up on a previously scored benchmark. No claim about the location of memory follows from a small loss difference. If it qualifies, the final comparison answers whether a genuinely isolated lane retains acceptable language-model accuracy at reduced parameter cost.
