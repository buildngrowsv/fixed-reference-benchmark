# Revisit the early fixed reference at 285 million parameters

At 31.99M weights, a readable fixed reference and its fully writable control finished 0.00197 bits per byte apart on CPython. That single-seed interval crossed zero. Reopen the comparison with ten blocks of width 1,536 and a 192-coordinate lane, three times the original width and lane size. This keeps the lane at one eighth of the residual stream and gives both arms the same approximately 285M stored parameters. The protected arm carries the last 192 coordinates from block 2 across seven intervening blocks, which may read them. The control permits writes. Both arms begin with the same zeros in output rows writing those coordinates and identical remaining parameters.

Use the archived seed-101 byte windows, optimizer, batch size, learning-rate warmup and update order. Inspect validation at 4,096 updates. Continue both to 16,384 updates if both beat 3.24 validation bits per byte, a basic task-learning check independent of the treatment difference. The second stage restores both model and optimizer. Evaluate final loss on the original 2,048 byte windows, paired by 49 held-out package groups. Report the small and large fixed-minus-writable differences and their interaction on the same windows. Treat a benefit as material at this budget if the large test improvement exceeds 0.02 bits per byte and its paired interval excludes zero. For evidence that the benefit itself grew with size, also require a negative upper bound on the interaction. Intermediate validation alone cannot decide either question. Report throughput, absolute losses and parameters. One corpus, one coupled training order and equal data exposure do not estimate performance at scale-optimal token budgets.
